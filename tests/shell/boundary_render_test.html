Shell error boundary — manual smoke (ICD-0.6.0 §13 E.01–E.02)

The shell exposes a ?force-throw=1 URL parameter that swaps the rendered route for a deliberate-throw component. The top-level Preact error boundary catches the throw and renders the fallback. console.error emits the structured [shell] boundary caught log.

Setup

  1. Start the kernel: ./build/plinth serve --config dev.toml.
  2. Open Chromium DevTools (Console panel visible).

Cases

E.01 Boundary catches synchronous render exception and renders fallback + logs to console.
  1. Navigate to http://localhost:8080/app/?force-throw=1. (You can submit a login form first if you want to test the authenticated route; the seam fires regardless of route.)
  2. Observe DOM: .boundary-fallback renders with "Something went wrong." text and a Reload button.
  3. Observe Console: a single [shell] boundary caught entry with a structured payload { error, info, route }.
  4. Expected: fallback DOM visible; console entry present; route field is the string "force-throw".
E.02 Reload button triggers a full page reload.
  1. From the E.01 fallback view, hold the Network panel open and check "Preserve log".
  2. Click the Reload button.
  3. Observe Network: a fresh GET /app/ document request fires (the page navigates from scratch — not an SPA re-render).
  4. Expected: new document request lands; ?force-throw=1 may persist if the URL hadn't changed (the reload is unconditional, not URL-cleaning — user's browser history dictates the post-reload URL). To recover the live shell, drop the query param and refresh.

Ship gate

Both cases must hold for 0.6.0 release. Headless coverage lands in the 0.6.0.N browser-test harness per OQ2 deferral.
