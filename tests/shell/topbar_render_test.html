Shell topbar render — manual smoke (ICD-0.6.0 §13 T.01–T.05)

Run after a successful manual login (see login_walkthrough_test.html). Each step's expected outcome must hold in the DOM or DevTools panel.

Setup

  1. Start the kernel: ./build/plinth serve --config dev.toml.
  2. Seed admin user if needed (see README.md).
  3. Open Chromium DevTools (Elements + Console).
  4. Navigate to http://localhost:8080/.
  5. Log in with seeded admin credentials.

Cases

T.01 Four .zone elements in DOM in order home → app-name → tray → avatar.
  1. In DevTools Elements, expand <header class="topbar">.
  2. Verify four child <div class="zone …"> in this order: zone-home, zone-app-name, zone-tray, zone-avatar.
  3. Expected: exactly 4 .zone children; classes match; no extra children.
T.02 Avatar zone shows username's first character (uppercased).
  1. Inspect .zone-avatar .avatar-circle.
  2. For seeded user admin, text content should be A.
  3. Expected: textContent === 'A'.
T.03 Click avatar → popover renders Sign Out menu item.
  1. Click anywhere inside .zone-avatar button.
  2. A .popover appears; inspect its children.
  3. Verify exactly one [role="menuitem"] with textContent === 'Sign Out'.
  4. Expected: 1 menuitem visible; text matches.
  5. Click outside the popover; verify it closes (popover unmounts).
T.04 Content area renders Hello, {username}.
  1. Inspect the <main> element under #root.
  2. Verify main.textContent.trim() === 'Hello, admin' (substituting the seeded username).
  3. Expected: exact match including comma and space.
T.05 Tray zone is empty.
  1. Inspect .zone-tray.
  2. Verify childElementCount === 0 (no children).
  3. Expected: zero element children. Whitespace text nodes are acceptable.

Ship gate

All five cases must hold for 0.6.0 release. Document any deviation in the CHANGELOG entry's "Implementation deviation" subsection per METHODOLOGY §Phase 2 Constraint #4.
