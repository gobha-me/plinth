Shell login walkthrough — manual smoke (ICD-0.6.0 §13 I.01–I.02 + L.01–L.06)

End-to-end: redirect, login form, authenticated frame, sign-out. L.\* wire-contract cases are deferred to 0.6.0.N per architect sign-off; they remain documented here as the manual checklist a human can run pre-0.6.0.N harness.

Setup

  1. Start the kernel: ./build/plinth serve --config dev.toml.
  2. Seed an admin user: ./build/plinth seed-admin --username admin --password <pw> (or use an existing user).
  3. Open Chromium DevTools (Elements, Network, Console panels).
  4. Open chrome://settings/cookies in another tab if you need to clear plinth_session between cases.

Integration cases

I.01 Navigate to / → redirected to /app/ → see login form → submit valid creds → see authenticated frame.
  1. Navigate to http://localhost:8080/.
  2. Observe Network: a 302 response with Location: /app/.
  3. Browser follows; final URL is /app/.
  4. Observe DOM: <form class="login-card"> renders.
  5. Submit valid admin credentials.
  6. Observe Network: POST /api/auth/login → 200 with Set-Cookie: plinth_session=…; HttpOnly; SameSite=Strict (Secure in production builds; absent in dev_mode).
  7. Observe DOM: four .zone divs in the topbar + main with Hello, admin.
  8. Expected: every step transitions in order; no Console errors; no CSP violations.
I.02 Sign Out from authenticated frame returns to login form; cookie cleared.
  1. From the I.01 authenticated state, click avatar → Sign Out.
  2. Observe Network: POST /api/auth/logout → 200 with Set-Cookie: plinth_session=; Max-Age=0.
  3. Observe Application → Cookies: no plinth_session cookie remains for the origin.
  4. Observe DOM: login form renders again under #root.
  5. Expected: cookie gone; login form re-renders; no Console errors.

Login wire-contract cases (deferred to 0.6.0.N)

L.01 Submit valid credentials → 200 + cookie + GET /api/auth/session returns user object.
  1. From login form, submit valid admin creds.
  2. Network: POST /api/auth/login 200; check Set-Cookie attributes (HttpOnly, SameSite=Strict, Secure when not dev_mode, Path=/, Max-Age non-zero).
  3. Follow with GET /api/auth/session; expect 200 + JSON body with user fields (username, id, etc).
  4. Expected: cookie attributes match; session endpoint returns user.
L.02 Wrong password → 401 + body.error == "invalid_credentials"; cookie not set.
  1. Submit valid username + intentionally wrong password.
  2. Network: 401 with JSON body containing error: "invalid_credentials".
  3. Application → Cookies: no plinth_session cookie set.
  4. DOM: login error region shows "Username or password is incorrect.".
  5. Password input cleared; username preserved.
  6. Expected: cookie absent; error string matches.
L.03 Empty username → 400 + body.error == "missing_username".
  1. Browser HTML5 validation usually catches this; bypass by removing the required attribute via DevTools Elements panel before clicking Sign In.
  2. Or use curl: curl -X POST http://localhost:8080/api/auth/login -H 'Content-Type: application/json' -d '{"username":"","password":"x"}'.
  3. Expected: 400 + body { "error": "missing_username" }.
L.04 Empty password → 400 + body.error == "missing_password".
  1. Similar bypass to L.03. curl -X POST … -d '{"username":"admin","password":""}'.
  2. Expected: 400 + body { "error": "missing_password" }.
L.05 6th rapid failed attempt → 429 + body contains retry_after.
  1. Submit wrong password 5 times in a row from one IP.
  2. 6th attempt: Network response is 429 with body { "error": "rate_limited", "retry_after": <seconds> }.
  3. DOM: form's submit button disables; countdown starts ("Try again in {N} seconds") per OQ3 resolution.
  4. Expected: 429; retry_after in body; UI countdown ticks down.
L.06 Sign Out clears cookie + subsequent GET /api/auth/session returns 401.
  1. From authenticated state, click Sign Out.
  2. Network: POST /api/auth/logout 200 with Set-Cookie: plinth_session=; Max-Age=0.
  3. In Console run fetch('/api/auth/session', { credentials: 'include' }).then(r => r.status); expect 401.
  4. Expected: 401; no plinth_session cookie returned with the request.
